# 实验协议（预注册模板）

**目的**：同一大模型与相同用户输入下，评价增加候选检索和硬约束复检后的改进。

- A 组：Direct LLM（输入结构化画像，输出相同 JSON 模式，没有外部候选筛选/规则修复）。
- B 组：FitMind AI（加入候选检索、结构化计划、业务校验与修复）。
- 30 组画像（24 组合 + 6 边界），15 条编辑指令；两个方法相同模型快照、温度、时间预算及输出 Schema。
- 两组各跑 30 个初始计划，另外各跑 15 个编辑场景，共计至少 90 次完整调用；出错也要记录，不要剔除失败数据。
- 使用预先定义的自动测试和 2 名盲评者，评分前不展示方法标签；争议案例由第三人复核。
- 每个输出按 `profile_id`、`system`、`model`、`timestamp`、`prompt_version`、`raw_output`、`validation_issues`、`latency_ms`、`tokens_in/out` 保存。

## 指标定义

1. 硬约束通过率 = 无任何违规的计划数 / 可评价计划总数；API 失败/解析失败单独报错率并在总体任务成功率中计为失败。
2. 编辑成功率 = 满足编辑意图且重新校验通过的编辑次数 / 全部编辑测试次数。
3. 无关内容保留率 = 未涉及编辑请求且保持不变的计划元素数 / 应保持不变的计划元素数。仅用于可比较的有效原计划。
4. 营养计算误差 = |展示值 - 依据食材重量复算值|；数据来自同版本数据集，单位 kcal 或 g；使用舍入容差 0.11。
5. 人工可用性 = 两位评审分别对表达清晰度、个性化相关性、执行可行性给予 1–5 分。
6. P50 / P95 延迟（ms）、token 和每次调用费用；记录模型价格来源与测量日期。

## 假设/解释

- H1：B 的硬约束通过率高于 A；H2：B 的编辑成功率与无关内容保留率更高；H3：B 可能增加调用时间或成本。
- 置信区间：配对 bootstrap（按 profile_id 重采样）或用 McNemar 检验比较配对的二元成功/失败；小样本解释为探索性研究。
- 结果图表需区分**目标阈值**与**真实观察值**，不得提前填写虚构结果。

## 安全与有效性说明

本实验验证约束遵循、计算正确性与可用性，并不证明减脂、增肌或健康干预的现实效果。
