# FitMind AI - 课程项目代码脚手架

这是一份**可运行的早期脚手架**，不是已完成的研究产品，也不是医疗或营养处方软件。

## 运行

```bash
python -m pip install -r requirements.txt
streamlit run app.py
```

不用 Key 时可运行**本地规则 Demo**（静态数据 + 规则组合，不应宣称为 AI 生成）。在环境变量中设置 `OPENAI_API_KEY` 后，界面的“大模型解析调整指令”会调用 OpenAI API 将自由文本解析为结构化意图，再由规则程序应用和校验。模型名称可由 `FITMIND_MODEL` 调整。

```bash
python -m pytest -q
```

## 已实现

- 用户资料输入、7 天示例计划展示和 JSON 导出
- 器械、可用训练日、饮食禁忌与营养数值规则校验
- 无 Key 时的基础正则编辑 Demo
- 有 Key 时的真实大模型**编辑意图识别**（需要联调）
- 4 个单元测试及小样本数据

## 小组必须继续完成（明确 TODO）

1. 引入真实 wger 和 USDA 数据，核对每 100 g 生/熟食材口径、数据版本与许可。当前 foods.json 全部为**课堂示例数值，不能作为正式营养数据库或医学依据**。
2. 开发 `planner_llm.py`：同一模型依据过滤后的合法候选动作与食材生成**完整结构化周计划**，并通过 `validate_plan` 校验；不要将本地规则计划作为 AI 输出。
3. 实现针对自然语言指令的局部修改，支持“日期调整”“替换单餐”等多种模式并保证其他内容不变。当前 Demo 改变禁忌食材时，可能替换多天相关菜品。
4. 增加基线实验 `Direct LLM`，同模型同格式，无数据过滤与硬约束修复。
5. 补齐实验：30 个配对输入、15 个修改情景；记录失败输出、模型参数、延迟、token 和人工盲评。
6. 安全：处理模型拒答、网络/API 故障；用户隐私和 API Key 管理；禁止医学场景自动给出处方。

## 注意

- `exclude_foods` 使用食物 ID；`allergies` 使用类别中文名称。
- 此代码刻意避免直接根据体重推断精确能量目标；课程若需要准确的营养规划，必须加入合理的边界、引用来源和专业审核。
- 将课堂示例数据替换为真实公开数据库之前，不能声明营养统计准确。
